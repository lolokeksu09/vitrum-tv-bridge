# BOXY Agent — приложение для Android TV 11

## Исправление прокрутки v0.4.0

На BOXY UI v0.3.0 слегка прокручивался вниз, поскольку вертикальные отступы и три отдельные информационные панели расходовали доступную высоту в dp. v0.4.0 объединяет сведения о канале и идентификаторе в один блок, убирает дублирующий нижний текст и повтор «Не настроен», уменьшает **только пустые промежутки** для TV-высоты менее 760 dp, сохраняет крупные шрифты и кнопки и при фактическом переполнении скрывает необязательный подзаголовок. Все кнопки и статусы остаются на главном экране. Наличие виртуальной клавиатуры или увеличенного системного масштаба всё ещё может потребовать прокрутки — содержимое не обрезается.

Изменения не затрагивают токен, Github API, permissions, Accessibility, командный протокол, CleanYourTV и настройки Android. Проверка CI подтверждает компиляцию/тесты, не реальную компоновку на приставке: для окончательного подтверждения нужен скриншот BOXY после обновления.


## TV-first интерфейс v0.3.0

Настройка под просмотр с дивана на расстоянии 4–5 метров: один экран
с двумя колонками (слева состояние, канал, ID и остановка; справа
публичный режим, токен и две основные кнопки), крупные шрифты,
контрастный AMOLED, видимый cyan focus по D-pad. Канал
`lolokeksu09/vitrum-tv-bridge` в интерфейсе фиксирован и не требует
ввода с экранной клавиатуры.

Флажок публичного режима заменён **на крупную кнопку-переключатель**
с явной надписью ВКЛ/ВЫКЛ. Согласие по умолчанию выключено и
сохраняется только после нажатия «Сохранить и включить».
Статус соединения и права Accessibility видны без прокрутки на
достаточно высоком TV viewport. На небольшом дисплее и при
экранной клавиатуре допускается вертикальная прокрутка, чтобы
не обрезать команды. Сброс токена требует подтверждения.

GitHub API, доступные команды, приватность, фоновый агент,
способ хранения токена и Android-разрешения **не менялись**.
v0.3.0 требует новой установки APK; CI debug-подписи между
сборками могут различаться. Если Android выдаёт
`INSTALL_FAILED_UPDATE_INCOMPATIBLE`, нужно отдельно подтвердить
удаление старой тестовой версии: сохранённые в ней локальные настройки
(включая токен) будут удалены. Не удаляй CleanYourTV.


## Публичный режим v0.2.0

Учитывая решение владельца **не создавать приватный репозиторий**, агент
поддерживает отдельный режим управления через уже существующий PUBLIC
`lolokeksu09/vitrum-tv-bridge`. Создание и обработка Issues не расходуют
минуты GitHub Actions. Это **осознанный компромисс приватности**:

- В приложении укажи `lolokeksu09/vitrum-tv-bridge` и установи флажок
  «Разрешить ПУБЛИЧНЫЙ vitrum-tv-bridge». Без флажка публичные репозитории
  отвергаются.
- Все Issue-запросы и статусы будут общедоступны; **не размещай пароли,
  токены, ключи VPN, конфигурации или скриншоты в Issue**.
- Владелец Issue должен быть `lolokeksu09`; команда привязана к device ID,
  времени создания (не старше трёх минут) и точному разрешённому набору.
- Публичный режим разрешён **только для точно указанного репозитория**.
  Запуск произвольного APK, shell, VPN-правки и скриншоты отсутствуют.
- Для работы нужен fine-grained GitHub token на **этот** репозиторий с
  правами Issues read/write; токен вводится только локально на ТВ.
- GitHub Actions не участвуют в выполнении команд, а используются только
  для выпуска новых версий APK.

v0.2.0 использует тестовую подпись GitHub Actions. При её несовпадении
с установленным v0.1.0 Android не позволит установить обновление поверх.
Потребуется удалить ранее установленный debug APK (это удалит его локальные
настройки) и установить новую сборку. После запуска проверить статус и
AccessibilityService на самом BOXY. При замене сборки оставь старый
Termux-мост до проверки настоящего соединения.


**Статус:** автономный агент на самой приставке BOXY (Skyworth HP44H,
Android TV 11, armeabi-v7a), исходники проекта. Это **отдельное приложение**,
не замена CleanYourTV, Vitrum TV или Android TV Home.

## Задача

После **однократной настройки** работает на приставке без Termux на телефоне:
- сохраняет GitHub-токен в Android Keystore; подключается к публичному
  репозиторию только после явного согласия владельца;
- запускает foreground service с видимым уведомлением, периодически проверяет
  новые команды владельца (раз в 45 секунд);
- возобновляет службу после `BOOT_COMPLETED`, если пользователь её включил;
- умеет `ping`, `home`, `back` и запуск строго четырёх избранных:
  `youtube`, `vkvideo`, `browsehere`, `v2rayng`;
- доступ к Home/Back и запуск приложений требуют **ручного разрешения
  AccessibilityService** через настройки Android TV.

Привилегированное ADB-управление, эмуляция всех кнопок пульта,
скриншоты, удаление приложений, очистка данных, VPN-профили,
обход системных диалогов и беззвучная установка APK **не реализованы**.
Обычное Android-приложение не обладает правами ADB shell/root.
Обновление кода агента требует новой подписанной версии APK и стандартного
подтверждения установки Android. Безопасный протокол не исполняет код из Issues.

## Первая настройка (один раз)

1. Используй **уже существующий публичный** репозиторий
   `lolokeksu09/vitrum-tv-bridge` — новый PRIVATE создавать не нужно.
   Создание Issue не тратит минуты GitHub Actions.
2. Выпусти fine-grained GitHub Personal Access Token **только для этого
   репозитория**, с правами `Metadata: read`, `Issues: read and write`.
   Не помещай токен в чат или в GitHub Issues.
3. Установи новую тестовую APK v0.2.0. Если старый debug APK v0.1.0
   подписан другим временным ключом, предварительно удали только
   `dev.lolokeksu.boxyagent` (настройки старой версии будут потеряны).
4. В приложении введи `lolokeksu09/vitrum-tv-bridge`, включи флажок
   «Разрешить ПУБЛИЧНЫЙ» и введи токен. Нажми «Сохранить и включить».
5. В «Специальных возможностях» Android TV включи BOXY Agent и вернись
   в приложение. Проверь статус подключения.
6. Передай в чат **только идентификатор устройства**, отображаемый в
   приложении, чтобы отправлять безопасные команды через Issues.
   В публичных Issue доступны имена операций и ответы; ничего личного
   туда не помещай.

APK обновляется через обычную установку Android; владельцу достаточно
провести **первичное** подключение. До завершения первичной настройки
агент не получает команд и не может быть удалённо установлен на ТВ.

## Протокол безопасного управления

В Issues выбранного репозитория создаётся новый Issue:

**Заголовок:** `BOXYAGENT/v1 ping`

**Тело** (device = идентификатор из приложения):

```json
{"v":1,"op":"ping","device":"<ID-ИЗ-ПРИЛОЖЕНИЯ>"}
```

Операции из ограниченного набора:
`ping`, `home`, `back`, `youtube`, `vkvideo`, `browsehere`,
`v2rayng`. Заголовок `BOXYAGENT/v1 <op>` должен совпадать с `op`.
Все запросы только от GitHub-пользователя `lolokeksu09`, возрастом не
более 3 минут, с точной схемой JSON и правильным ID устройства.
Проверяется владелец и режим видимости: private по умолчанию либо
разрешённый по явному согласию PUBLIC `vitrum-tv-bridge`.
Результат отправляется в Issue выбранного репозитория и Issue закрывается.
В публичном режиме результат виден всем; никаких секретов или диагностических
данных в ответах нет.

Для исключения повторных нажатий номер команды записывается **перед**
выполнением: после сбоя сети результат может не быть опубликован, но команда
не будет повторно выполнена без новой заявки. Каждая установка запрашивает
разрешение Accessibility отдельно.

## Разработка и CI

Модуль: `boxy-agent/`; Java 17, Android Gradle Plugin 8.7.3,
Gradle 8.9, `minSdk=26`, `targetSdk=30`, без сторонних runtime SDK.

GitHub Actions `BOXY Agent — build test APK`: выполняет
`gradle --no-daemon :app:testDebugUnitTest :app:assembleDebug`,
выкладывает APK в артефакт `boxy-agent-debug-apk`.

Сборка на GitHub Actions **не доказывает** успешный запуск на BOXY;
до установки тесты Android runtime/Accessibility/boot = NOT RUN.
Сохраняй работающий Termux-мост до реального подтверждения готовности
нового агента; не отключай ADB заранее.

## Известные ограничения

- Для установки APK первый раз потребуется стандартное разрешение Android.
- Без Accessibility можно только проверить `ping`.
- OEM может ограничивать автозапуск и уведомления фоновых служб.
- Действие запуска приложения подтверждает передачу Intent, но не гарантирует,
  что сторонняя программа завершила инициализацию.
- Нет права на silent update и доступ к данным других приложений.
- Нужен fine-grained token; для PUBLIC требуется явное согласие на экране и строго определённый репозиторий.

## Целевой repository design

**Отдельный чистый** репозиторий, предварительное рабочее имя `Scrcpy-RU` (имя не зарезервировано и репозиторий сейчас не создан). В корне — Android `app/`, Gradle, `docs/`, `README.md`/ `README.ru.md`, CI и license/third-party attribution. Исходник переносить контролируемым git fork или vendor import с сохранением происхождения и применением проверенного RU patch. В целевой репозиторий **не копировать** код `vitrum-tv-bridge`, git history screenshots/captures, issues или secrets.

Рекомендуемое разветвление после переноса: `main` = стабильная версия; `feature/profiles-v1` = реализация; `feature/android-tv-remote` = независимая фича после профилей; `spike/scrcpy-5-protocol` = исследование и прототип без гарантий.

## Процедура переноса (ещё не выполнена)

1. Создать новый пустой приватный GitHub repo под собственным аккаунтом (в текущем подключении GitHub нет действия create repository; нельзя считать его созданным).
2. Импортировать только upstream pinned source, отразить авторство и оригинальные лицензии.
3. Перенести `scrcpy-ru/apply_to_source.py`, ru resources, help content; применить локализацию к source. Поместить документы в `docs/`.
4. Настроить workflow из текущего проекта на source-in-repo, исключить ссылки на bridge; закрепить версии action/dependencies по отдельному техническому аудиту.
5. Сборка/ресурсные тесты, APK sha256, smoke test на Android, затем удалить старую временную точку входа **отдельным решением**, не автоматически.
6. При необходимости открыть исходный проект для публичного распространения **только после** аудита лицензий, отсутствия приватных артефактов, секретов и сторонних прав.

## Do not mix

Не вносить Scrcpy изменения в `vitrum-tv-bridge/main`, `Vitrum`, `MONOLITH`, `MONOLITH-TV`. Не объединять Git history временной сборочной площадки с будущим Android репозиторием. Временная площадка пригодна для сборки и передачи плана, но не заменяет отдельный чистый репозиторий.

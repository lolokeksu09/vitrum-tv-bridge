# PROFILES — контракт Profiles v1

Статус: **спецификация, ещё не код**. Названия существующих опций берутся из `app/src/main/java/ro/sw3g/scrcpy/Options.java` upstream commit `d4a9a8c`.

## 1. Структура профиля

`Profile`: `id` (UUID), `name` (1–64 символа), `transport` (`tcp` или `usb`), `host` (строка для TCP), `port` (число 1–65535, только TCP), `settings` (известные ключи `Options.fields()`, значения в текущем строковом формате), `interactionMode` (0 — прямое касание, 1 — тачпад-жесты, 2 — тачпад-кнопки).

Локальное хранилище: `schemaVersion: 1`, `activeProfileId`, `profiles: []`. Каждый профиль содержит собственный полный набор 35 опций; неизвестные или недостающие ключи при миграции нормализуются через задокументированные defaults и не запускаются как произвольные команды.

Пример **формата**, а не экспорт текущего устройства:

```json
{
  "schemaVersion": 1,
  "activeProfileId": "f7dd9475-52d4-4718-96d4-214e2988b838",
  "profiles": [{
    "id": "f7dd9475-52d4-4718-96d4-214e2988b838",
    "name": "Android TV",
    "transport": "tcp",
    "host": "192.0.2.10",
    "port": 5555,
    "interactionMode": 2,
    "settings": {
      "max_size": "1280",
      "max_fps": "60",
      "video_bit_rate": "8000000",
      "video_codec": "h264"
    }
  }]
}
```

`192.0.2.10` — документационный адрес; неполный пример `settings` при чтении дополняется дефолтами. Файл хранения после нормализации должен содержать все 35 ключей.

## 2. Что относится к профилю

- TCP endpoint, настройки видео/аудио/камеры, управление/мышь/запись, `extra` с теми же серверными ограничениями.
- USB-профиль хранит понятное имя, но не `UsbDevice.getDeviceName()` как постоянный аппаратный ID: Android может его изменить. При нескольких USB ADB устройствах оставлять выбор устройства.

## 3. Что никогда не хранить и не экспортировать в профилях

`adb-identity.bin`, RSA private key, pairing code, пароль, журналы, скриншоты, записи сессий, permission grants, детали USB-авторизации, произвольные shell команды. Язык интерфейса, `usbAuto`, настройки логирования — общие настройки приложения, а не устройства.

## 4. Хранилище и транзакции

- `ProfileStore` (новый класс) хранит `profiles.json` в private app storage через `AtomicFile`; использовать последовательную запись и проверку схемы до записи.
- Сначала проверить `ProfileValidator`, затем сохранять целый snapshot атомарно. Ошибка чтения/записи не должна стирать старый снимок.
- До миграции сделать резервное чтение старого `SharedPreferences("settings")`. Первое создание профиля `Текущее подключение` идемпотентно; сохранение marker только после успешной атомарной записи.
- После миграции прежние prefs и `adb-identity.bin` не удалять. Запуск без `profiles.json` и с уже сохранёнными prefs должен быть безопасным.
- Импорт ограничить размером, версией и списком известных полей. Содержимое `extra` проверять по существующему `Options.server()`/каталогу. **Никакого автоподключения сразу после импорта**.
- Для экспорта показывать предпросмотр адреса; секреты отсутствуют по модели. Системный файловый диалог открывать только после явного действия пользователя.

## 5. Смена профиля и текущая сессия

Смена активного профиля не изменяет текущий `Session`. Для нового профиля пользователь отключается, затем вручную подключается; позже можно добавить явное подтверждённое «Переподключить». При старте создать неизменяемый `Options` snapshot из выбранного профиля.

## 6. Минимальные тесты

- Первая миграция сохраняет все существующие поля, host, port и выбранный mode.
- Повторная миграция не создаёт второй профиль и не переписывает пользовательские изменения.
- Два профиля не разделяют изменяемую map; после перезапуска значения независимы.
- Некорректный порт, codec, отрицательные численные значения и неизвестные `extra` отклоняются до записи.
- Ошибка записи/невалидный JSON не уничтожает последнюю валидную версию.
- ADB identity неизменна; удаление профиля не удаляет её.
- Переключение профиля во время активной сессии не пересоздаёт соединение и не меняет его параметры.

# Profiles v1 — реализация и проверка

Статус: feature branch \`feature/scrcpy-profiles-v1\`, **экспериментальная отдельная сборка**, не замена стабильной RU 1.5.1.

## Что добавлено

- \`ProfileCodec.java\`: версия JSON-схемы, валидация идентификаторов, адресов, портов, режимов, нормализация отсутствующих известных параметров, запрет неизвестных ключей.
- \`ProfileStore.java\`: приватный атомарный файл \`profiles-v1.json\` через Android \`AtomicFile\`. При первом запуске перенос существующих \`SharedPreferences("settings")\` в профиль «Текущее устройство». Исходные preferences и \`adb-identity.bin\` **не удаляются**.
- Связь с \`MainActivity\`: список профилей, выбор, создание, редактирование, копирование, удаление (не последнего), подключение выбранного профиля; независимые значения \`Options.fields()\`, host, port, interactionMode.
- Настройки сохраняются в профиль при выходе со страницы или перед соединением. Параметры уже идущей сессии — это отдельный неизменяемый \`Options\` snapshot.
- Добавлены 19 строк интерфейса для EN/RO/RU. Старые экраны USB, Wi-Fi ADB, консоли и справки сохранены.
- Добавлены JUnit-проверки сериализации, изоляции snapshots, отказов на повреждённых данных и неизвестных полях.

## Особенности пробной сборки

Чтобы не удалять установленный \`ro.sw3g.scrcpy.ru\` с прежней **другой debug-подписью**, feature APK использует пакет \`ro.sw3g.scrcpy.ru.profiles\` и название «Scrcpy RU Profiles». Он устанавливается параллельно.

**Важно:** из-за Android sandbox новая параллельная сборка **не может автоматически читать настройки и ADB-ключ старой RU-сборки**. Внутренний код миграции работает, когда обновление происходит внутри **того же** приложения/пакета при действительной совместимой подписи. Для тестового \`.profiles\` пакета нужно один раз ввести IP/порт и разрешить новый ADB-ключ на целевом устройстве. Запрещено удалять старую RU-сборку ради эксперимента.

## Границы

- Нет фонового сканирования локальной сети, автоматического pairing, экспорта ADB-ключей или удалённого выполнения shell.
- Текущий scrcpy server 3.3.4, wire protocol и Session остаются без изменений.
- Группировка 35 настроек и ТВ D-pad относятся к следующим этапам.
- Если \`profiles-v1.json\` повреждён, интерфейс показывает ошибку и сохраняет прежний способ ручного подключения; повреждённый файл не перезаписывается автоматически.
- Ручное отключение/автопереподключение сохраняют прежнюю логику.

## Критерии приёмки

1. Сборка и 7 unit tests (\`ProfileCodecTest\`) проходят в **одном и том же SHA**.
2. \`aapt dump badging\` показывает пакет \`ro.sw3g.scrcpy.ru.profiles\`, версию \`1.6.0-profiles-v1\`; \`apksigner verify\` проходит.
3. На реальном телефоне проверить создание двух профилей с разными параметрами, переключение, перезапуск приложения и подключение к Android TV.
4. Зафиксировать ошибки авторизации, неверный IP, редактирование и удаление последнего профиля.
5. Не заявлять устройство проверенным, пока нет результатов установки/управления именно данной APK.

## Дальнейшие задачи

- Улучшить управление неполными/некорректными исходными настройками (предупреждения при миграции).
- Добавить UX-группировку настроек, Android TV пульт и расширенную диагностику по ROADMAP.
- После тестирования перенести продукт из временной сборочной ветки в отдельный приватный Android-репозиторий.
